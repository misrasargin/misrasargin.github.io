Did the promotion work? An A/B test planner

Method report for the interactive page.

Summary

The page is a tool for one decision: a shop wants to know whether a new offer raises the share of visitors who buy. It plans the test (how many visitors, how many weeks), reads the result (difference, interval, p-value), and shows by simulation why checking a running test every day is a mistake. The planner

The outcome is yes or no for each visitor, so the comparison is a two-sided test of two proportions. For a baseline rate p₁ and a target rate p₂, the visitors needed in each group are

n = ( z1−α/2 √(2 p̄ (1−p̄)) + zpower √(p₁(1−p₁) + p₂(1−p₂)) )² ÷ (p₂ − p₁)²

where p̄ is the average of the two rates. The number of days is n divided by half the daily visitors, and the planner rounds that up to whole weeks so every weekday is represented equally. The power curve on the page uses the same formula solved for power, and “the smallest lift you can find in two weeks” solves it for the lift by bisection.

Does the formula deliver?

A formula can be typed in wrong, and it rests on a normal approximation. So I checked it two ways.

  • Against SciPy. analysis/check_formulas.py runs the JavaScript functions and compares them with an independent Python calculation. Sample sizes are identical and every other value agrees to six decimal places.
  • Against simulation. For six kinds of shop I simulated tests at the recommended size, with a real lift and with none.

The peeking problem

A p-value below 0.05 is rare under no effect only if you look once. A running test wanders, and if you stop the first time it crosses the line you pick the luckiest moment. I simulated tests with no difference at all ( visitors per group, buying in both), checked them at equal steps, and stopped at the first p below 0.05.

Reading a result

The checker reports the difference in percentage points with a 95% interval (unpooled standard error) and a two-sided p-value (pooled standard error, the usual z-test). The interval matters more than the p-value: a result can be “not significant” while the interval still includes a lift worth having, which means the test was too short, not that the offer failed.

Limitations

  • Visitors are assumed independent and counted once. Repeat visits make the real uncertainty larger.
  • Only yes-or-no outcomes are covered. Revenue per visitor is skewed and needs a different test.
  • The normal approximation is poor when very few visitors buy. The planner’s sample sizes are large enough that this rarely bites, but the checker can be fed small counts.
  • The planner assumes an even split and steady traffic.
  • Novelty effects, seasonality beyond the week, and several offers tested at once are outside its scope.

Reproduce it

pip install -r requirements.txt, then python analysis/simulate.py for the simulations and python analysis/check_formulas.py for the formula check (it needs Node.js to run the JavaScript). The seed is fixed.
